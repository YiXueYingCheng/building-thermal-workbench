# 建筑导入修复（v0.73.13）

本修复已纳入 v0.73.13 公开预览版，包含门构造和导入核对路径修复。以下验收在隔离副本进行，私人反馈原件及实际研究资料不随公开包分发。

此前，预检查仅接受已核对木门，转换程序也把门厚统一固定为 25.3 mm。含金属门的数据库因此无法继续导入。

现在，已核对的木门继续使用原参数；与已核对单层阳台铝门构造和物性匹配的记录使用 10 mm 厚度、220.97 W/(m·K) 导热率、2600 kg/m³ 密度和 482 J/(kg·K) 比热。厚度和单位已对照来源软件的门库、材料库界面确认。比热保留源库值，不以其他资料的典型值替换。该铝门的 CONDUCT_CO 为 0 不再作为实体层的热阻：实体层按厚度除以导热率计算热阻，并保留密度和比热对应的蓄热。

导入页面分别列出每类门的名称、数量、材料、厚度及物性，用户逐项确认后才转换。确认绑定当前检查参数；参数变化或漏选时不能沿用旧确认。旧木门记录及原来的 25.3 mm 确认方式保持兼容，混合门型不能借用旧的统一木门选择。

转换继续使用表面热吸收率 0.85、太阳/可见光吸收率 0.55 和 MediumSmooth 粗糙度近似。页面与审计记录明确列出这些假设，须与厚度、物性一并确认；它们不是该铝门表面的实测值。不能把本次适配理解为已验证所有金属门、带玻璃门、夹芯门或空气间层门。

每类门的原始记录摘要、采用参数、厚度依据和确认摘要保存在检查及转换记录中；自然室温与温控模型使用同一门构造。源 ACCDB、旧方案和旧结果不因这项修复而重写。

已有“源检查未通过”的记录保留。应用包含本修复的版本后，重新点击“检查所选文件”，在新检查记录中逐项确认门参数，再转换并加入建筑列表。

验证范围：反馈的 30 扇门记录为 24 扇木门、6 扇铝门；另以修补版 Drawing26 几何构造隔离测试，验证全木门和混合门型的完整导入、输入生成、登记及两日引擎试算。未取得反馈建筑的完整数据库，因此尚未验证该 33 房间建筑的全部几何与配置。

另一次反馈在保存核对临时文件时提示找不到路径。截图中的临时路径长 267 个字符，超过传统 Windows 260 字符限制；长路径支持还取决于系统及应用配置。参见 [Microsoft 路径长度说明](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)。

本次缩短实际生成的名称，而不仅减少层级：

| 项目 | 原名称规则 | 新名称规则 |
| --- | --- | --- |
| 新导入目录 | import_ + 32 位编号 | import_ + 12 位编号，重名时重新分配 |
| 独立核对目录 | 嵌套 input-validation 工作区 | data/checks/c_ + 12 位编号 |
| 导入核对输入目录 | inputs_ + 32 位摘要 | i_ + 12 位摘要，仅用于独立导入核对 |
| 输入暂存目录 | .preparing_ + 32 位编号 | .p- + 8 位随机名，独占创建 |
| JSON 临时文件 | 原文件名再加随机编号 | t- + 8 位随机名 + .tmp，独占创建 |

完整身份、SHA-256、参数及来源引用仍保存在 JSON 记录中。短名称不替代内容核验。已有目录不重命名，旧导入记录的查询和登记继续兼容；正式计算输入包的既有命名约定也保持兼容。导入验收记录明确保存新的核对目录与清单路径，空间管理将其列为核对证据。

在与截图相同的 102 字符工作区路径下，模拟未启用长路径支持的 Windows：旧临时名在 267 字符处失败，新版本最长转换临时路径为 174 字符，混合门型完成检查、转换、自然室温/温控输入核对及登记。另核对了重名保护、新旧编号的实际 HTTP 查询，以及原子写入失败时旧文件保持不变。此次路径验证没有重新运行建筑模拟，也没有更改 Windows 设置。

若安装位置更深且仍超出限制，程序会先探测当前进程的实际写入能力。已经支持长路径的环境可继续使用；确实无法保存时，给出明确的路径提示，不再只报告缺失文件。既有失败记录保留，使用包含修复的版本重新检查所选建筑即可。
