# v0.73.13 异地反馈修复与新增设置

适用于 v0.73.13 公开预览版。本次整合原 localfix.1–6 的本地验证修复，包括门构造和短路径修复；公开包只包含程序、已授权随包资源和说明，不包含反馈电脑的原始研究资料或隔离工作区。

## 房间作息与导入准备

- 导入前明确提醒：先在原建筑模型中设置、核对墙体、屋面、楼板、门窗等基础围护结构，不要预先叠加本次研究材料，避免重复加载。研究材料的加载与作用位置在平台设置；基础构造调整宜回源模型修改后重新导入。
- 原公用库已有 8 份可精确还原为工作日／周末的房间配置，但导入下拉框遗漏了 reference 分组。现在恢复该分组，与 3 份演示配置分别展示。同名用途优先显示，仍须人工选择并核对参数，不作为规范值或适用性结论。
- 已知用途与完整通道参数继续展示；原建筑没有用途记录时明确显示“用途未标注”，不推测用途。来源缺少许可证字段时不显示空值；原许可文件保持。
- 同建筑房间复用增加按类型筛选、勾选当前筛选房间、取消当前筛选勾选和勾选与来源同类型。新导入使用来源类型编号，旧导入没有编号时按已有用途名称分组；未标注用途不能自动匹配为同一类型。
- 筛选不清空其他已勾选目标。批量勾选后仍需预览、应用、保存建筑配置和方案版本，原有方案和结果不自动改变。
- 修复“实际值切换为上下限 × 比例后回退”：此前只检查原作息已核对，未确认原作息确为比例形式。现在只在原参考确为比例形式且与当前实际值等价时恢复它；其余情况根据当前实际值新建比例作息。原配置可以完全没有比例参考，零值计划也能创建后编辑。切换本身先保持实际值，调整上下限或比例后才改变计划。空调可用仍为独立 0/1 计划。

## W00 外墙光学参数推广

在“查看建筑平面与材料位置 → 选择外墙 → 查看此墙构造”中，先编辑来源墙面，再选“推广外表面光学参数”。适用于可编辑的普通导入建筑方案，包括不附加研究材料的 W00。

- 同类以建筑原构造的完整层序、材料类别和原始参数一致判定；构造名称不同但内容相同仍可匹配。原构造不同的墙面不混选。
- 可分别选择太阳吸收率、热发射率、可见光吸收率，按朝向、楼层、房间筛选，勾选目标或全选当前筛选。筛选保留其他范围已勾选的目标，并明确显示数量。
- 预览逐面显示原值与新值；确认采用后进入方案草稿，仍需保存方案版本。参数已相同的墙面不增加修改。来源或目标发生变化时须重新预览。
- 仅复制最外层选中的光学参数；各墙已编辑的厚度、导热率、密度、比热、其他光学字段和其余层全部保留。基础几何、门窗、内墙、屋顶、研究材料与控制不改动。
- 已绑定库构造的墙面继续遵守原编辑限制，不通过批量入口覆盖。已有外侧研究层时，基础墙体参数不代表最终暴露表面的参数。
- 同一查看窗口内可撤销上次光学推广；目标发生后续编辑时拒绝直接撤销，避免丢失修改。关闭窗口后通过既有方案草稿撤销／保存版本流程处理。

验证：9 组前端逻辑检查；真实后端接受批量结果；浏览器完成筛选、预览、采用、撤销、重新采用、保存 v2、刷新并重新打开。隔离 Drawing26 方案从来源 S_983 推广到 5 面同类东向墙。编译后仅这 6 面（含手动修改的来源墙）最外层太阳吸收率和热发射率改变，其他原模型对象及历史版本保留。未启动新的建筑模拟，未改动正式研究资料。

## 文件夹气象导入

在“气象导入”窗口增加“文件夹批量导入”：可包含子文件夹，逐份检查 EPW、显示质量明细，修改地点名称，勾选后明确登记。相同内容复用既有有效副本；同名不同内容分别保留；文件改变、缺失或质量不通过时单项报告，不丢弃其他已完成项。

逐份请求显示进度，支持完成当前文件后停止。关闭窗口停止后续请求；已提交的当前项会完成，已登记内容保留。重新扫描可核对剩余项，重复登记不会重复创建内容副本。不自动覆盖原气象来源，不改变任何方案范围。

跳过链接／重解析项；一次最多列出 500 份 EPW、遍历 1000 个文件夹或 20000 个文件项，到限后提示分批。气候类型默认未分类；需要分类或来源更新时使用单文件入口记录依据。

## 全球气象连接问题

2026-11-17 用户纠正此前反馈：JRC（re.jrc.ec.europa.eu）的气象可以下载，受阻的是原预选中的 TMYx 来源（climate.onebuilding.org），中国地区下载成功。此前“全球地点全部失败”的描述已撤回。Tunnel connection failed: 502 Bad Gateway 表明该次请求在建立代理隧道时失败，不能据此判定全部国外来源不可用或气象文件无效。

增加代理隧道、HTTP、超时、安全连接和一般连接的分类提示，不回显代理凭据。同一来源出现代理隧道故障后保留后续项目待处理，其他来源可继续；已完成项不重复下载。连接恢复后可点击“重试原来源／继续未完成项”。

程序继续使用现有系统网络配置与证书校验，不自动绕过代理、不替换登记的数据版本、不移除文件校验。可在反馈电脑点击“提供方原文件”核对该站点访问，或自行取得原始 EPW 后按文件夹导入。

## 可选 CPU 调度控制（2026-11-18）

“计算队列 → 设备投入”增加整机 CPU 当前、近期平均值，以及“按 CPU 占用控制新增并行”开关。旧工作区默认关闭，原并行、内存和磁盘设置保持。建议初始目标为 80%；可自行设置 10–100%，点击“应用设备投入”后对本工作区后续派发生效。

内存及磁盘限制始终有效。开启 CPU 控制后，派发还要求当前和近期平均负载中较高者，加上新增一路 CPU 预算，不超过目标。新算例先按一个逻辑处理器的占比预留，若本轮已有进程实测峰值更高则上调；每次启动后观察约 10 秒，避免在负载尚未升高时连续加任务。负载不足、观测失效或尚在观察期时等待，恢复余量后自动继续；已运行任务不终止、不暂停、不改变模拟步长。用户选择过低目标时，连首个算例也可能等待，需提高目标或关闭此控制。

界面显示派发原因、单路预算与正在运行算例的 CPU 观测。预算页给出当前余量参考；原“按并行上限均分的理想耗时”仍是理论值，未把 CPU 百分比换算为精确耗时，也未承诺并行越多越快。CPU 限制属于派发控制，不能硬性保证整机占用一直低于目标，其他软件和单个已运行算例仍可能造成超出。

采样采用 Windows `GetSystemTimes`，系统内核时间包含空闲时间，只扣除一次；当前显示按全机忙碌时间计量的占比，近期窗口约 10 秒。任务管理器可能使用不同计量方式，数值不保证完全一致。多处理器组设备当前不声称取得可靠整机负载，开启 CPU 控制时停止新派发并说明原因，关闭后内存限制仍可使用。每个引擎进程的观测使用 `GetProcessTimes`，按逻辑处理器数折算整机百分比。
