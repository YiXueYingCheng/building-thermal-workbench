# 空间占用、方案版本与结果受控清理

适用版本：v0.73.11 公开预览版；保留已验证范围，本次不扩展清理功能。

提供空间账、结果关联查看、浏览缓存清理、失败／取消尝试清理、已通过结果的“清理明细、保留汇总”，以及未被引用的研究方案／保存版本删除。各入口分别限定目标，都要先预览，再明确确认；不会连带删除其他资料。结果清理继续保护待复核、专项复核、逐日参考、共享及外置结果；方案删除继续保护只读来源、对比集成员和所有仍被引用的版本。

## 删除方案或单个保存版本

先进入“编辑方案”，选中方案。左侧“方案管理 → 查看方案删除影响”预览整个方案；“查看版本记录 → 查看此版删除影响”预览单个版本。查看影响本身不删除。存在未保存的方案或房间配置编辑时，先保存或撤销，再打开删除预览。

| 选择 | 确认后移除 | 继续保留／后续行为 |
| --- | --- | --- |
| 单个版本 | 仅所列版本快照及该版当前备注 | 其余版本内容和编号不变；删掉最新版后回到剩余的最新版；删除最后一版时该方案也不再显示 |
| 整个方案 | 预览中列出的全部保存版本及这些版本的当前备注 | 不会顺带删除另存方案、建筑、材料、作息、日历、气象、输入、准备清单、任务、结果、比较、对比集、导出或已有备份 |
| 仅预览或取消 | 无 | 所有版本和资料保留；只新增预览记录 |

**有引用时不删除，也不会自动解除引用。** 会检查其他方案全部保存版本中的另存／来源追溯、已保存比较、对比集的当前和历史版本、输入、准备、计算任务、日历、汇总、导出、受管验证记录及已登记外置结果中的元数据。明确引用 v1 不会阻止单独删除无引用的 v2；未注明版本或不能确定用途的引用按保守规则保留。隐藏、归档和旧版本中的引用同样参与检查。只读来源及对比集成员不在本次删除范围；整个对比集的删除另行安排。

预览会显示目标名称、版本号、是否包含当前备注、删除后的最新版或方案消失状态、阻塞原因、关联用途和保留范围。关联项可展开看具体来源。无法读取的元数据、异常路径及共享硬链接数据库也会阻止删除，不按“没有引用”处理。平台外手工复制的资料无法自动追踪；浏览缓存不属于研究引用，按当前数据库重新读取。

预览有效期 15 分钟。只有无阻塞且明确勾选确认后，才能点击“确认删除列出的版本”。执行前重新核对版本、备注及引用；期间发生变化就要求重新预览。排队／运行任务、后台输入准备、复核、其他页面请求、数据库写入或未结束的备份会阻止执行。

版本、当前备注及删除记录在同一次数据库事务中完成：其中任一步失败，整次撤回；已经提交的同一预览重复发送只返回原删除记录。删除不自动重算、不修改剩余版本，也不改写历史接受结论。操作历史、备注修改历史和删除记录继续保留，因此这不是抹除全部历史痕迹。版本内容删除后没有直接撤销按钮；恢复需要已有备份，宜按工作区备份／隔离恢复流程核对，不要手工改库。

版本号不重排、不复用。例如删除 v2、v3 后保留 v1，再保存会产生 v4。版本记录中的变更对照改为相对上一**保留版本**，并列出已删编号。删除最后一版后方案不再显示；新建或另存方案会有独立编号。

左侧“查看删除记录”显示最近 20 次方案／版本删除，包含方案、版本、当前备注删除数、保留范围和时间。删除主要整理方案库，不自动压缩数据库，也不承诺释放固定磁盘容量。需要释放计算明细空间时，应使用下方独立的结果清理入口，不能靠删除方案来绕过结果保护。

## 查看占用

进入顶部“空间管理”，点击“重新统计”读取当前工作区、随平台资料和已登记的其他计算结果位置。按方案与任务登记、输入、准备证据、原始结果、汇总导出、缓存、公共资料、备份和程序分类。按路径、方案名称或批次搜索；每页最多 30 组。

展开条目可看位置、文件数、最近修改时间和已知任务引用。结果按运行尝试归组，并列出任务登记中的批次与方案保存版本；旧尝试和被多个任务引用的文件分别保留。未匹配登记表示需要进一步核对，不表示可以删除。

统计范围以实际列出的位置为准，不扫描整块磁盘，也不递归跟随符号链接、目录联接或其他重定向。仅被方案引用、但不在这些目录内的原始建筑文件、引擎及其他来源，不计入这里的目录总量。外置位置先核验原登记目录与磁盘身份，无法读取时标记“未知／待核对”；部分可读目录显示已知部分，不能把未读部分算作零。

“文件体积”是文件内容长度；“去重贡献”在本次扫描范围内按文件身份去重，同一文件或硬链接不重复累加。它们不是磁盘分配簇、压缩后占用或必然能释放的容量。共享文件在某一组计入去重贡献，其他组仍保留文件条目和共享提示。

## 清理浏览缓存

1. 点击“预览浏览缓存清理”，查看逐项对象、预计文件体积、需要保留的项目和重建影响。此步骤生成预览记录，不删除文件。
2. 可直接取消。若确认只清理所列缓存，勾选确认后执行。
3. 执行时重新核对位置、文件身份、时间和摘要；变化过的缓存、共享硬链接、异常文件或非标准条目保留。运行／排队任务、输入准备、组任务或结果核对未结束时拒绝清理。未完成的备份临时包也会阻止执行。
4. 完成后查看删除数、保留数及具体原因。部分失败不影响说明和记录，可重新预览剩余项。

缓存入口的范围仅为 `data/navigation-cache/view-*.json` 中结构与校验均正确的浏览缓存。它们用于列表、平面和流程读取，可以重新生成，不作为计算输入和科学结果接受的依据。下次首次打开相关页面可能稍慢。

方案、版本、材料、计算输入、原始结果、导出、公共资料和备份均保留。清理不级联删除，也不修改已保存的日历、对比绑定或复核结论。方案归档／恢复继续使用原方案库；归档不等于释放磁盘空间。

预计删除量、成功删除文件的体积和执行前后观察到的磁盘可用空间变化分别报告。删除直接作用于所列缓存，不移入同盘回收目录；磁盘空间变化可能受到其他程序写入、文件系统分配及清理记录本身影响，不能完全归因于本次操作。预览有效期为 15 分钟，重复提交已完成的同一预览只返回原执行记录。

## 查看结果关联及清理失败尝试

1. 在“空间管理”选择“原始计算结果”，点击某次运行的“查看关联与清理”。窗口显示任务状态、保存位置、关联资料、候选文件、阻塞原因及预计可清理体积。预览不删除文件。
2. 核对本工作区的数据库及受管 JSON 证据，包括保存方案、两两比较、对比集结果绑定、已生成输入、日历及逐日参考、复用索引、结果摘要、复核和导出。条目区分直接文件引用、批次引用及关联方案；后两种按保守原则保留，不宣称已确定某个具体算例被使用。隐蔽、归档或旧版本引用也参与检查。平台外手工复制的资料无法自动追踪。
3. 仅允许有唯一当前任务归属、状态为失败／已取消、没有结果登记和运行进程、没有其他引用的**本地**尝试。通过、待复核、复用、中断、未知或仅有历史归属的尝试都保留。外置位置本轮只检查关联，不提供删除；无法读取的位置与异常元数据会阻止清理，不视为没有引用。
4. 候选文件严格限于对应 `runs/<尝试编号>/run/` 下的 `eplusout.sql`、`eplusout.csv`、`eplusout.eso`、`eplusout.mtr`。保留原任务状态及报错、模型输入、所有 JSON、ERR／END 等诊断日志；不删除目录，不清理其他算例，也不删除来源文件。**删除后不能检查这些文件中的原始明细；需要时必须明确重试计算，平台不会自动重跑。**
5. 明确勾选后才能执行。执行时重新核对引用、任务状态、路径和逐个文件的身份、时间、摘要。新增引用或重新排队会阻止清理；已更新、共享硬链接、不可读的文件逐项保留。数据库写入和调度期间拒绝执行；HTTP 处理中的生成、读取、导出与清理互斥；后台准备／复核未结束时保护。备份与结果清理共享进程间锁。链接及目录联接不跟随。
6. 清理记录逐项写入，分别显示成功、保留及原因。执行意外中断时可能有“删除操作尚未确认”的条目，应重新统计核对，不能当作已删除或已释放。重复提交同一个预览返回原记录，不继续执行未确认的项；部分失败请重新预览剩余文件。

“预计可清理”在有阻塞时为零，候选文件仍可查看；不是说这些文件不占空间。本轮没有对真实研究资料执行清理，所有删除验收均使用专门创建的隔离测试文件。

## Agent 使用现有业务入口

所有写请求沿用本机工作台的会话校验。根目录由服务确定，不接收外部任意路径。

| 操作 | 接口与关键含义 |
| --- | --- |
| 只读统计 | `GET /api/storage-management`。`complete=false` 表示有未知或部分读取的位置；未知字节数为 `null`。 |
| 查看清理记录 | `GET /api/storage-management/history`，返回最近 20 条记录。 |
| 预览缓存清理 | `POST /api/storage-management/preview`，内容 `{}`。返回 `id`、`sha256`、逐项文件、保留项、阻塞原因和预计文件体积。 |
| 查看结果关联 | `GET /api/storage-management/result-impact?attempt=attempt_<32位编号>`，只读，返回归属、引用及保留原因。 |
| 预览失败文件清理 | `POST /api/storage-management/result-preview`，内容 `{"attempt":"attempt_<32位编号>"}`。`dependencies` 给出关联与限制；`blocked` 非空不可执行。 |
| 执行失败文件清理 | `POST /api/storage-management/result-execute`，传原预览 `id`、`sha256`、`confirmed:true`；必须取得对应文件范围的明确确认，不能从“继续开发”推断获准删除真实资料。 |
| 明确执行缓存清理 | `POST /api/storage-management/execute`，传原预览的 `id`、`sha256` 和 `confirmed: true`。应先向使用者展示影响并取得对应范围的确认；不能直接修改预览文件或数据库。 |
| 预览保留汇总的明细清理 | `POST /api/storage-management/retention-preview`，内容 `{"attempt":"attempt_<32位编号>"}`。返回 `inspection`、逐项 `files`、`blocked`、`impact`、`id` 与 `sha256`；预览只写预览记录，不删除文件。 |
| 确认保留汇总的明细清理 | `POST /api/storage-management/retention-execute`，传原预览的 `id`、`sha256`、`confirmed:true`。须取得所列真实文件范围的明确确认；没有确认时只能预览，不能用“继续开发”代替删除授权。 |
| 预览方案／版本删除 | `POST /api/plan-deletion/preview`，整个方案传 `{"id":"draft_<32位编号>","scope":"record"}`；单版另传 `"scope":"version","revision":2`。返回 `inspection.target`、关联 `references`、`blocked`、保留 `kept` 及预览 `id`／`sha256`。 |
| 执行方案／版本删除 | `POST /api/plan-deletion/execute`，传预览 `id`、`sha256`、`confirmed:true`。需要对应目标和版本范围的明确授权，不可从开发授权推定获准删除实际方案。目标和引用仍会重新核对。 |
| 查看方案删除记录 | `GET /api/plan-deletion/history`，只读，最近 20 条。回执记录 `removed_versions`、`removed_current_notes`、`latest_after`、`files_deleted:0`；不要套用文件清理的体积字段。 |

返回的 `removed_file_bytes` 是成功移除文件的内容长度，`observed_disk_free_change` 是磁盘观察值，两者不相等是可能的。`retained` 与逐项原因用于后续处理，不能将“部分成功”报成全部已清理。

此前过渡版验收只在隔离副本删除生成的测试文件和专门复制的结果明细。实际研究工作区仅安装功能并核对，没有删除研究资料；该次验收未发布 GitHub、未启动新计算。

v0.73.10 的方案／版本删除验收另使用隔离工作区内本轮新建的测试方案；复制进去的既有版本全部保留。真实工作区只核对影响和取消，不执行删除。当前代码支持这一流程，不代表已替使用者清理任何方案。


## 核对结果资料与可用能力

结果索引、计算队列批次和空间管理的结果关联窗口提供“核对结果资料”。先选择批次和算例，再检查本次文件。批次列表不扫描大结果；逐项核对有时间上限，超时显示未知，不当作一致。可以关闭窗口继续操作。

历史“通过／待复核／复用”保留当时的登记结论；本次另外检查汇总校验值、算例身份及所列原始文件。分别显示核对一致、缺失、校验不一致、已受控清理或未知；保存位置不可访问时不冒充文件已删除。汇总本身未通过核对时不展示数值。手工删失或损坏的文件没有匹配的受控清理记录时，比较、结果读取及新导出仍拒绝使用该结果；此窗口可只读展示校验通过的原汇总。待复核数值不成为已接受结果。

“资料条件满足”只是现有业务进一步核对的前提，不保证比较口径、复用身份或复核方法匹配。文件完整不代表含逐时数据，不能按求解步长猜测输出频率。

窗口内可展开“如果只保留汇总、清理计算明细，会怎样”，也可点击“预览明细清理，保留汇总”。每项能力分别说明是否仍满足资料条件，不能把保留汇总理解为保留全部分析能力。

只读接口：`GET /api/result-availability?batch=<批次编号>` 列出算例；加 `&index=<从0开始的序号>` 核对一项。返回 `registered_status` 与本次 `state`、`summary_verified`、`artifacts_verified`、逐项 `files`、`capabilities` 和不可执行的 `retention` 影响说明。接口不写库、不保存接受结论、不删除、不重新计算；不得用这个核对替代原采用或计算入口。

## 清理明细，保留原已接受汇总

入口：结果索引、计算队列或空间管理 →“核对结果资料”→ 核对具体算例 →“预览明细清理，保留汇总”。

1. 预览列出将清理的文件、关联用途、保留内容、损失的能力及阻塞原因。未勾选确认，或有阻塞时，执行按钮不可用。取消保留本次全部文件；预览有效期 15 分钟。
2. 首批仅允许本工作区中有唯一当前任务归属、常规核验通过、没有运行进程的独立结果。专项复核、待复核、逐日参考、其他任务共享或复用、未知用途引用、外置结果均保留。已保存的两两比较、对比集及本工作区已有导出可继续使用汇总，因此允许保留这些关系；复用索引不会使缺失原始明细的结果继续被自动复用。
3. 文件范围仅为对应运行目录的 `run/eplusout.sql`、`eplusout.csv`、`eplusout.eso`、`eplusout.mtr`。不删除目录、JSON 汇总、模型输入、日志或其他文件。只清理实际预览列出的文件，不追踪或清理工作区外手工复制的资料。
4. 明确确认后，执行时再次核对全部关联、任务状态及候选文件；运行、排队、后台准备／复核、数据库写入或备份会阻止清理。路径链接、硬链接共享、文件变化及不可读项保护规则与失败尝试清理相同。删除直接作用于所列明细文件，不能从汇总还原。
5. 每个文件先登记待执行，再记录确认删除或保留及原因。原任务、汇总数值、接受范围和警告均不改写。发生部分失败时只承认已确认删除的项，可重新预览剩余文件。重复提交同一个预览只返回原记录；意外中断留下“删除尚未确认”时不能据此放行缺失资料，应从备份恢复原文件并核对，或另行调查后处理，平台不会猜测成功或自动重算。

经受控清理后，只有清理记录与原任务、原汇总及每个缺失文件的校验值全部相符，且其余必需文件未变化，才启用“保留汇总”读取。单批次结果、两两比较、三／四工况对比集可继续读取与导出原来已有的时段、月度和房间汇总；适用口径、方案版本和原接受范围仍需匹配。不会根据汇总补出逐时曲线或重新判定科学结论。

页面明确标记“保留汇总结果”；新导出 CSV 带保留状态列，JSON 带清理证据标识，导出包包含 `保留汇总说明.txt` 与 `summary-retention.json`，图表标注 `Retained summary; raw details removed`。清理前已导出的静态文件不被改写。所需原始资料缺失时，自动复用、重新复核、逐日／日历参考及明细分析仍拒绝执行；恢复这些能力需找回校验一致的原文件，或明确另行计算。
