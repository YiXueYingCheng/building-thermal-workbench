# 升级到 v0.73.15（公开版及 rc.1 至 rc.9）

本包是 v0.73.15 公开预览版。支持下列官方版本升级：v0.72.2、v0.73.11 至 v0.73.14，以及 v0.73.14-rc.1 至 rc.9。适用范围是**原路径升级**。新安装请看 [安装说明](INSTALL.md)。

## 开始前

准备好新包和正在使用的旧平台。**将新包解压到另一个文件夹，不要直接覆盖旧平台。** 记下旧平台所在的完整文件夹路径：应能看到 `Start Workbench.cmd` 和 `building-workbench-next` 文件夹。

先保存页面上的编辑，等计算、输入核对和导出完成，关闭其他正在操作该工作区的页面。运行升级助手时不要重新启动旧平台。已登记的外置结果盘都要接通；备份位置需要容纳平台资料和这些结果的一份完整副本。

本工具使用已安装的 64 位 Python 3.12，仅用标准库。新包尚未建立 `.venv` 也可以运行助手；旧环境仍保留，本版与支持的旧版本的锁定依赖相同。若双击提示找不到 `py` 或 Python，请先按安装说明修复 Python 3.12 安装。

## 按这个顺序升级

1. 在**新解压的包**中双击 **`Upgrade Workbench.cmd`**。
2. 输入 `1`，选择“升级旧平台”。粘贴旧平台的完整路径，按回车。不要填 `building-workbench-next` 子目录，也不要填新包目录。
3. 助手会显示旧、新版本、将更新的文件数量，以及已登记的外置结果位置。检查是不是要更新的那个平台。
4. 选择备份位置。默认是在旧平台旁边新建带日期的备份文件夹；直接回车即可，也可填写其他有足够空间的完整路径。备份不能放进旧平台、新包或结果文件夹里面。
5. 确认页面编辑已保存、计算/核对/导出已结束后，输入 **`升级`**。助手核对并停止这个旧平台的网页服务及已确认空闲的计算后台，先复制平台资料及外置结果，逐文件校验通过后才更新。检测到等待或运行中的计算时会停止操作，不会强行结束引擎。
6. 等到出现“**升级完成**”，记下备份位置。然后在**原来的旧平台目录**双击 `Start Workbench.cmd`。新功能现在从原位置打开，配置和保存路径保持。
7. 对照升级前核对：旧方案和历史版本能打开、旧结果数值一致、比较能选择原批次并导出、外置保存位置正确。材料版本、旧三工况集合不自动改造；新功能不会自动提交计算。

备份和升级耗时取决于结果数量，助手会显示正在处理的位置。不要在复制过程中关闭窗口。遇到错误先保留窗口文字和备份，不要换成“全覆盖”重试。

## 更新、保留和备份的范围

| 内容 | 处理方式 |
| --- | --- |
| 程序、页面、文档与明确列入发行清单的随包资源 | 核对原文件后更新；发现用户修改或同名新增文件时停止，并列出冲突 |
| 原 config.json | 保留：端口、Python 与路径配置不被默认值覆盖 |
| data、runs、生成的 assets、方案版本、材料/作息版本、比较和结果 | 原位保留，升级前同时备份 |
| 计算程序兼容记录 | 精确核对官方旧版执行文件，追加仅用于读取和复核旧结果的记录；原计划、模型、数值和警告不改写。尚未提交的旧计算清单需重新准备，不能直接沿用提交 |
| 登记在平台中的外置结果文件夹 | 升级前备份，升级时不修改、不搬移；未接通则停止升级 |
| .venv、.git、Python 缓存 | 不重复备份；升级时保留原位。恢复时 `.venv` 和 `.git` 回到原路径；缓存可再生成 |
| 未列入更新清单的自建文件、下载气象 | 原位保留；在平台目录内的文件一同备份 |
| 平台目录之外的原始建筑、气象、引擎及其他外部来源 | 不搬移、不修改、不自动备份，仍需保留原路径和自己的原始资料副本 |

新包的 `MANIFEST.sha256` 校验的是原始下载包；升级后的旧平台保留自定义配置，不能用它要求整个工作区与新包完全相同。实际更新文件、原路径、备份位置和完成状态记录在旧平台根目录的 `UPGRADE_RECEIPT.json`，备份目录中另有 `BACKUP.json` 和 `UPGRADE.json`。

## 升级后需要恢复怎么办

1. 保存当前编辑，等正在进行的计算、核对和导出结束。保留错误信息，不要先删除新结果或覆盖目录。
2. 在新包中再次双击 `Upgrade Workbench.cmd`，输入 `2` 选择“从备份恢复”。
3. 填写升级前备份目录的完整路径，该目录应包含 `BACKUP.json`。助手先核验所有备份文件，再显示将恢复的平台和外置结果位置。
4. 输入 **`恢复`**。助手停止对应服务，将当前平台和外置结果分别另存为带 `before-restore` 的同级文件夹，再把备份恢复到原路径。保留备份本身，并生成 `RESTORE-日期.json` 操作记录。
5. 出现“恢复完成”后，从原路径启动。应看到升级前的版本、方案和结果。升级后新增的方案和结果保存在刚才另存的现场副本中，**不会自动合并进旧数据库**；需要时从现场副本另行取用，不要直接覆盖 SQLite 文件。

恢复需要额外空间容纳一份备份内容；旧、新研究资料都会保留。如果磁盘空间不足、备份校验失败或恢复途中报错，不继续启动平台，也不要删除现场。错误和 `RESTORE-日期.json` 会说明已完成的位置，保留它们便于处理。

## 常见提示

- **发现自行修改或同名新增文件**：助手未覆盖它们。先将修改另存到平台之外，再核对哪些属于原发行文件；不要为了升级直接丢弃自己的修改。
- **还有等待或运行中的计算**：回到原平台完成任务或正常停止，确认状态后再运行助手。
- **请先接通已登记的结果位置**：恢复磁盘连接并检查文件夹；工具不会把离线结果当作空目录。
- **新包校验不通过**：重新取得并完整解压原始包。不要编辑清单绕过校验。
- **更新未完成，请勿启动平台**：备份已保留，使用恢复入口先还原；不要在半更新状态下继续研究。

本次支持上述官方版本原路径升级；不支持将任意 localfix 工作副本直接当作官方旧包升级，也不自动合并或移动研究数据库。若旧程序被改过，助手列出冲突并停止。

升级后可在“设备投入”中核对 CPU 控制、并行上限与内存预留。已有完整结果可读取、比较、导出和复核；仍按原文件校验，升级不替你采用警告。旧计算清单若提示程序更新，请重新准备后再提交；需要更细时间尺度也须重新计算，旧月度数据不会变成逐时数据。

请先核对旧方案、版本、结果、比较和保存位置，再继续新计算。

升级后首次启动时，工作台为已有对照保存双方当时的方案版本。请先在原目录完成升级并打开工作台，再整理旧示例。可从“已保存的两两比较”打开双方配置和已有结果，核对历史记录。
