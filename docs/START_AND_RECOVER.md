# 普通 Windows 启动与计算恢复

AI 可以协助安装和核对，但日常使用建议由你在普通 Windows 会话启动：完成安装后，在文件资源管理器中进入平台包根目录，双击 `Start Workbench.cmd`，再使用打开的网页。不需要管理员身份。

如果平台原来由 AI 工具或受限任务环境启动，手动点击它的网页不会改变后台进程的权限。若日志出现工具环境的权限或文件操作限制，先保存页面编辑，等当前计算完成或按平台流程正常暂停、结束对应后台，再从普通 Windows 窗口启动。关闭网页通常不会停止后台；再次双击启动器也可能找到原服务，因此要确认旧服务确实已停止。可让原启动者停止自己启动的对应平台，或按明确的进程身份处理；不要批量结束所有 Python / EnergyPlus，也不要删除 `worker.lock` 来强行启动。

平台不会修改 Windows 执行策略、文件夹权限或 AI 工具保护设置。普通 Windows 启动也不能解决文件夹本身的拒绝访问、磁盘离线或文件被其他程序占用，仍需按具体错误处理。

## 计算队列中不同动作的含义

- **检查并启动后台**：检查进程和新心跳，确认后台完成中断恢复检查；不自动解除任何批次的暂停。启动失败时在队列顶部显著显示原因，可展开、复制诊断。
- **继续此批次的排队项**：后台就绪后只解除选中批次的暂停，按 CPU、内存、磁盘和并行预算派发；不会重试中断项。
- **重试失败 / 中断项并继续此批次**：后台完成恢复检查后，将本批这些项目重新排队并继续。旧尝试文件和已完成结果保留，不影响其他暂停批次。

“后台已运行”不等于“当前有算例正在计算”：批次暂停或等待资源时都可能运行数为零。后台进程存在但心跳过期时，页面会提示状态未知，不反复生成后台进程，也不强行结束已有计算。

## 写检查和升级提示

结果位置在提交批次时进行写入、回读检查；每个算例仍核对磁盘身份、目录标识和剩余空间，并执行实际文件写入，但不再为每个算例重复生成写检查临时文件。写入或回读失败仍报错；已完成写检查后的临时文件清理失败单独记录警告，保留该文件，不批量补删或改变保护规则。

升级助手对 Windows 短暂文件锁进行有限重试，并减少重复写入进度文件。最终仍逐文件核对。真正权限不足不会无限重试或假报成功；错误中保留原始原因。若显示“程序文件已校验通过，但回执未完整保存”，说明文件更新和状态登记不同步，请按提示保留备份、恢复核查，不能把它当作完整成功。
