# 结果明细与输出频率

原逐日入口适用于 v0.73.11 及以后。v0.73.13 本地候选已增加输出频率选择与原变量时序读取，见 [批量采用与输出时间尺度](BULK_REVIEW_AND_OUTPUT.md)。大型算例体验仍待进一步试用。

## 从哪里进入

在计算队列或结果索引打开已有批次，再打开一个算例的结果明细，点击“查看输出频率与时序明细 ↗”。“核对结果资料”窗口也提供同一入口。

先显示原 SQL 实际保存的时间频率，以及变量、原对象名称、单位和统计方式。查找原变量时可输入中文；登记输出项不代表每一时刻都有数值，具体范围读取时还会核对完整性。

“5 分钟求解步长”并不表示保存了每 5 分钟的输出。没有保存的逐时室温、材料状态或冷热需求不能从月度／整个时段汇总还原；平均状态也不能当作精确切换时刻。

## 查看整栋建筑或单个系统的逐日冷热需求

在“逐日冷热需求”中，默认查看整栋建筑。每一行是当日全部理想负荷系统的供暖、制冷和合计，单位为 kWh。可查看当月、自选日期或整个计算时段，也可选择一个系统查看连续 1—31 天。整栋建筑的日表须覆盖已登记的全部系统，对完整模拟月份还会核对逐日之和与月度汇总。

在“导出本批数据包”中勾选显热冷热需求的“逐日”，打开包内的 daily.csv 即可按地点、算例和日期读取整栋建筑的日表。monthly.csv 提供对应月表，case-*.csv 提供所选指标的原始明细。

- 原输出单位为 J，按 3,600,000 J/kWh 换算为 kWh，保留每日累积口径；它是显热需求，不是耗电量或瞬时功率。
- 沿用原系统名称，没有依据系统名称推测房间归属。房间室温、表面状态与系统需求的对应关系尚未在这一入口接通。
- 只使用一个正式天气计算环境，排除明确标记的预热数据。日期保留原模拟日历，不替换为当前年份、不按浏览器时区转换。CSV 保留 SQL 年、时间记录编号和日间隔。
- 缺项、重复、时间基准不同、错误单位或负数需求均停止读取，不补零、不插值、不悄悄缩短范围。
- 修改系统或日期后，原图表和导出入口失效，重新读取后才显示新选择的数据。
- 当前范围 CSV 带批次、算例索引（从 0 开始）、结果身份、汇总及 SQL 校验值、原接受状态和完整数值。下载到浏览器设置的下载位置，不写入研究结果目录。

这个入口不改变历史接受结论；待复核结果会保留提示。它不能替代逐日光学切换参考核验，也不会将普通结果自动登记为参考。

## 文件、数据量与边界

打开某个算例才读取该算例，查看批次列表不扫描全部原始结果。每次先核对登记汇总和其 SQL 的内容校验值，再进行只读查询；结束时复查文件与登记有无变化。受控清理或手工删失 SQL 后，汇总仍按原有规则处理，但此入口无法读取明细。

整栋建筑每个模拟日返回一行汇总。单个系统每次最多读取 31 天。原 SQL 不增加索引、不修改文件；文件校验仍读取完整文件，原库缺少查询索引时 SQL 仍可能扫描较多数据。设置读取时间限制，并分开记录文件核对及目录／数据读取耗时。这不能作为大型结果已经完成性能优化的结论。

本轮用现有 9 个结果核对输出：都没有逐小时／逐步时间记录，其中 1 个有逐日冷热需求。该结果 6 个系统的 72 次分段读取与原年度供暖、制冷总量闭合。另用合成百万行数据检查有限返回量；它不是大型建筑计算，也不是冷缓存测试。

## 当前候选与后续范围

v0.73.13 已接通按原变量／对象读取逐日、逐时、区域步明细及 CSV，完成独立短算例验证。房间、系统、表面之间的联动分析仍未接通。新输出频率只改变记录方式；既有月度结果仍按原记录读取，不会自动重跑年度方案。用户现在可明确批量采用完整的待复核结果，详见上方专门说明。

大型结果还需验证独立索引或缓存的收益、失效规则及空间代价，再考虑扩大读取范围。连续热过程不能按月独立计算后拼接。

字段依据：[EnergyPlus SQL 输出说明](https://bigladdersoftware.com/epx/docs/22-2/output-details-and-examples/eplusout-sql.html)。实际频率以文件内的 Time 与 ReportDataDictionary 为准。
