# 批量采用与输出时间尺度

批量采用和输出频率设置自 v0.73.13 提供。v0.73.14 新增批次数据包的指标与频率选择。

## 导出批次数据包

打开“本批结果”的数据包导出入口。在“选择数据包内容”窗口按指标勾选需要的时间尺度，再点“生成所选数据包”。只需要全批次的汇总、核验状态和来源时，清除时序选项，点“仅导出基础汇总”。

热阻调节和表面光学切换各有自己的状态记录。窗口按各算例实际保存的指标和频率列出选项，只有部分算例有记录时会标出数量。例如求解步长为 1 分钟、状态只保存了逐日均值时，导出可取得逐日状态；精确切换时刻需要更细的原始记录。

## 批量强制采用待复核结果

在“计算队列 → 查看结果与核验”打开含待复核结果的批次，点击“强制采用待复核结果…”。

1. 选择当前批次或整个工作区，检查并预览清单。
2. 弹窗列出可采用、完整性未通过、失败和未完成的数量，并可展开原警告。
3. 填写审阅人、采用说明和用途范围，勾选确认，再点击强制采用。

强制采用记录的是用户决定使用结果，不表示平台证明警告无害。已完成且完整性核对通过的待复核结果会以“用户强制采用”参与比较与导出；原始结果、模型、日志、警告保持，另存采用记录。采用时再次核对绑定与文件，发生变化的项目单独保留原状态，其余项目继续处理。

计算失败、中断、未算完或资料不完整的项目不能被补造成有效结果。“失败原因与处理”和“下载失败诊断”提供现有错误与日志；修正原因后，在队列重试失败／中断项。重试保留旧尝试文件。原有的逐项复核流程继续可用。

关闭检查窗口后任务仍在后台进行；同一页面重新打开可继续查看。服务重启后已登记的采用结论保留，其余项重新预览。整个工作区的范围是本次预览捕获的待复核记录，不会顺带采用之后新增的结果。

## 设置输出频率

从方案的“计算安排”进入，在“结果保存的时间尺度”选择：

| 选择 | 适用场景 | 每个输出项全年时间点（非容量估计） |
| --- | --- | ---: |
| 逐月（默认） | 总量和月度比较 | 12 |
| 逐天 | 日需求和日间趋势 | 365 |
| 逐时 | 日内温度、需求变化 | 8,760 |
| 逐步 | 不超过 31 天的短期诊断，间隔随求解步长 | 5 分钟全年等价为 105,120 点；界面不开放整年逐步 |

所有选择继续保留月度与整个计算时段汇总。改变的是记录频率，不改变求解步长、材料、控制或模型物理参数。重新准备对应清单后，仍须明确提交才计算；旧清单和旧结果保留。恢复输入准备记录时保留它的输出频率。

保存内容包含模型原有的变量请求以及房间温度、适用系统的显热冷热需求。对象数量与变量数量都会增加文件量。本设置没有自动增加所有可能的设备／湿空气诊断变量，也不把能源需求当作耗电量。

原有仅月度的结果不能还原逐日、逐时或逐步数据。要获得更细的数据，需选择频率并重新计算所需算例。较细输出保存各自的明细与月度汇总，没有额外保存所有中间频率。

## 查看与导出

在算例明细打开“查看输出频率与时序明细 ↗”。显示的是已保存 SQL 中的实际频率，而非根据求解步长推测。

- 有成对逐日冷热需求时，原来的逐日图表和 CSV 继续可用。
- “按输出项查看时序”支持逐日、逐时和区域步，选择原变量／对象及日期读取。
- 单次一个变量／对象、最多 31 天和 12,000 个时间点。表格最多展示前 300 行，CSV 保留本次选择的全部记录；超过上限会提示缩短日期，不抽样或补零。
- 时间为模拟当地时间的区间结束时刻；24:00 表示当天末尾。Avg 为区间均值，Sum 为区间累积量。保留原单位、接受状态、强制采用说明和来源校验值。
- 此处不自动建立房间、系统、表面之间的对应关系；它不是联动诊断图，也不代替表面光学切换逐日参考的专项核验。

## 空间影响与本地验证范围

点数乘以变量、对象与算例数量后才是数据规模；SQLite 基础开销、索引、极值记录等也占空间，不能把时间点比例直接当文件体积比例。空间预算按输出类型区分历史样本，没有同类样本时不会沿用月度样本。

本轮对同一两天跨月算例完成四次真实 EnergyPlus 计算，汇总冷热需求一致；SQL 分别约 240、252、280、656 KiB。这只是该小算例实测，不代表全年或大型建筑的占用。另验证了生成输入到准备清单的完整链路、频率对应的独立身份、明细与月度闭合、异常明细拒绝、批量确认、登记后绑定变化、失败诊断下载和原文件保留。

大型全年逐时输出的运行时间、磁盘开销和交互体验仍需实测。读取时会核对原 SQL 内容，文件越大核对时间越长；未通过增加缓存或修改原 SQL 来规避这个成本。
